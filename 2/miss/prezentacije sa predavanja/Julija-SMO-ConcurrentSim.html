Simulacija diskretnih događaja u Julija jeziku upotrebom ConcurrentSim paketa

Simulacija diskretnih događaja se može vršiti pomoću više paketa, među kojima su ConcurrentSim i DiscreteEvents. ConcurrentSim je 2023. godine nasledio ranije korišćen SimJulia paket i zadržao je ideju zasnovanu na korutinama (implementiranim u ResumableFunctions), dok DiscreteEvents upotrebljava asinhrone metode koje komuniciraju preko kanala (Channels). Tokom simulacije DiscreteEvents prolazi kroz ekvidistantne vremenske trenutke sa konačnom (zadatom) rezolucijom, dok u ConcurrentSim rešenju korutine skaču u proizvoljne vremenske trenutke.

Treba naglasiti da se implementacija navedenih funkcionalnosti menja u zavisnosti od verzija korišćenih paketa (navedeni primeri su rađeni za verzije ConcurrentSim v1.5.0).

Osnove ConcurrentSim paketa

Inspirisan je Simula bibliotekom - DISCO i Python bibliotekom SimPy. Ponašanje aktivnih komponenti (poput klijenata, automobila, mašina, itd) se modeluje procesima. Svi procesi postoje i izvršavaju u se u okruženju i interaguju sa okruženjem i međusobno preko događaja. Rad je zasnovan na asinhronoj obradi događaja u toku simulacije, pri čemu događaji mogu biti sortirani po prioritetu, vremenu nastanka, i sl. Komponente koje učestvuju u simulaciji su: simulaciono okruženje (Simulation), procesi (process) i događaji (event). Događaji mogu da imaju listu callback-ova i povratne vrednosti. Pored toga, simulacija obezbeđuje tri i tipa deljenih resursa: resurse (Resources), kontejnere (Containers) i magacine (Stores).

Procesi u ConcurrentSim su korutine koje raspoređuje implementacija iz ResumableFunctions paketa. Znači, proces se definiše kao @resumable function i unutar njega se generišu događaji i/ili se čeka na njih. Ako funkcija procesa očekuje događaj, njeno izvršavanje se obustavlja dok se događaj ne desi i obradi. Događaji se kreiraju uz upotrebu @yield makroa i smeštaju se u listu događaja koja se procesuira tokom simulacije. Tu je upravljanje procesima zasnovano na kontrolama raspoređivanja procesa implementiranim u ResumableFunctions paketu.

Osnovni koncept za simulaciju diskretnih događaja podrazumeva definisanje okruženja u okviru koga se definišu procesi i ti procesi programski generišu događaje, a rad procesa se obustavlja sve do trenutka kada se događaj dogodi (trigeruje). Posebna vrsta događaja je timeout koji se raspoređuju u tačno definisano vreme (između koga proces „spava“), a koji se definiše u okviru okruženja (env) kao:

@yield timeout(env, time)

pri čemu time predstavlja vremenski period nakon koga proces „oživljava“.

Kada se događaj desi proces koji čeka na njega nastavlja sa radom i tada dobija i vrednost događaja. Na primer:

using ResumableFunctions
using ConcurrentSim

@resumable function example(env::Environment)
    event = timeout(env, 1, value=42)
    value = @yield event
    println("now=", now(env), ", value=", value)
end;

sim = Simulation()
@process example(sim)
run(sim)

now=1.0, value=42

U gornjem primeru je u procesu example kreiran događaj timeout sa argumentima okruženjam (env), vremenom čekanja (1) i povratnom vrednošću (value=42) koja se vraća nakon aktiviranja događaja, tj. nakon isteka vremena čekanja u simulacionom okruženju env. U svakom trenutku moguće je očitavanje simulacionog vremena iz okruženja pozivom now(env).

Pokretanje simulacije podrazumeva da je prethodno kreirana instanca Environment pomoću npr. naredbe Simulation u cilju sinteze svih procesa i događaja i upravljanja simulacionim vremenom.

Za pokretanje simulacije se koristi:

  • run(env) – bez vremenskih ograničenja

  • run(env,tk) – za unapred definisano simulaciono vreme (0,tk), ali u 0 i tk nema događaja

  • umesto vremena simulacije, kao drugi parameter se može poslati događaj, tako npr. run(env, timeout(env,5)) je ekvivalentno sa run(env,5)

@resumable function clock(sim::Simulation, name::String, tick::Float64)
    while true
        @yield timeout(sim, tick)
        println(now(sim), " ", name)
    end
end

sim = Simulation()
@process clock(sim, "prošlo 15 sekundi", 15.0)
@process clock(sim, "prošao MINUT", 60.0)
run(sim, 120)

U prethodnom primeru su definisana 2 procesa gde se generišu događaji isticanja vremena. Poziv @yield u jednom procesu prepušta izvršavanje drugog procesa i biva blokiran dok se ne desi događaj na koji čeka, tj. dok ne istekne vreme. Na kraju, događaji u 120-toj sekundi nisu procesuirani jer je vreme simulacije isteklo.

Važno je primetiti da se simulacija sprovodi u simuliranom vremenu tako da se ceo proces simulacije brzo završava.

Funkcija koja opisuje proces može da vraća vrednost:

@resumable function my_proc(env::Environment)
    @yield timeout(sim, 1000)
    150
end;

Ta vrednost može biti korišćena od strane drugog procesa:

@resumable function other_proc(env::Environment)
    ret_val = @yield @process my_proc(env)
    @assert ret_val == 150
    println(now(sim), " ret-val=", ret_val)
end;

U ovom primeru proces koji izvršava other_proc pokreće process my_proc i čeka da se završi.

sim = Simulation();
@process other_proc(sim);
run(sim);

1000.0 ret-val=150

Nadalje će biti ilustrovana upotreba paketa na nekoliko jednostavnih primera bez želje da se ilustruju sve mogućnosti paketa.

Primer - Automobil

Proces car opisuje ponašanje automobila gde se simuliraju stanja parkiranja i vožnje automobila (ispisuje se aktivnost automobila, tj. stanje u kome se nalazi).

Ovaj primer je preuzet iz dokumentacije paketa i njegov programski kod je ostavljen neizmenjen, te su nazivi promenljivih i komentari na engleskom jeziku.

using ResumableFunctions
using ConcurrentSim

@resumable function car(env::Environment)
    while true
        println("Start parking at ", now(env))
        parking_duration = 5
        @yield timeout(env, parking_duration)
        println("Start driving at ", now(env))
        trip_duration = 2
        @yield timeout(env, trip_duration)
    end
end;

Proces car je definisan kao @resumable funkcija u kojoj se u beskonačnoj (while true) petlji periodično izvršava sledeći postupak:

  • Parkiranje automobila – traje 5 v.j. (vremenskih jedinica) nakon čega se izvršava

  • Vožnja automobila – u trajanju od 2 v.j.

Beskonačna petlja omogućuje da se simulacija izvršava u trajanju koje korisnik definiše, a u delu @yield timeout(env, parking_duration) se specificira vreme “trajanja” aktivnosti parkiranja (praktično „uspavljivanja“ procesa), nakon čega se nastavlja izvršavanje programa.

Kreiranje okruženja se vrši pomoću funkcije Simulation() nakon čega se definiše konkretan process (u ovom slučaju car()) u formiranom okruženju. Simulacija se pokreće upotrebom naredbe run sa definisanim okruženjem i vremenom simulacije.

sim = Simulation()
@process car(sim)
run(sim, 15)

Start driving at 5.0
Start parking at 7.0
Start driving at 12.0
Start parking at 14.0

Interakcija procesa

Čekanje na proces

Ukoliko se u simulacionom okruženju definiše više procesa moguće je implementirati čekanja jednog procesa na drugi. Tako, na primer, ranije definisani process car() koji podrazumeva kretanje i parkiranje automobile može da zavisi od drugih procesa, kao što su npr. pranje automobila, punjenje automobila (električnog), popravka, i sl. Pretpostavimo da je definisan dodatni proces charge() za punjenje električnog automobila.

@resumable function charge(env::Environment, duration::Number)
    @yield timeout(env, duration)
end;

Ukoliko se automobil u okviru procesa car() parkira i puni, onda se u okviru procesa car() pokreće novi proces charge() i čeka se završetak procesa charge() kako bi process car() nastavio sa izvršavanjem. Navedena aktivnost je prikazana u kodu na sledeći način:

@resumable function car(env::Environment)
    while true
        println("Start parking and charging at ", now(env))
        charge_duration = 5
        charge_process = @process charge(sim, charge_duration)    # registrovanje novog procesa
        @yield charge_process                                     # čekanje da se proces završi
        println("Start driving at ", now(env))
        trip_duration = 2
        @yield timeout(sim, trip_duration)
    end
end;

te se nakon pokretanja nove simulacije dobija:

sim = Simulation()
@process car(sim)
run(sim, 15)

Start parking and charging at 0.0
Start driving at 5.0
Start parking and charging at 7.0
Start driving at 12.0
Start parking and charging at 14.0

Prekidanje drugog procesa

Pored čekanja da se drugi proces završi, moguće je i prekinuti njegovo izvršavanje. Prekid procesa se vrši upotrebom interrupt() funkcije. Na primer, neka je formirana funkcija driver() za opis procesa koji će prekinuti drugi proces (car_process):

@resumable function driver(env::Environment, car_process::Process)
    @yield timeout(env, 3)
    @yield interrupt(car_process)
end;

i to tako da se nakon 3 v.j. prekida proces opisan drugim argumentom funkcije.

Ukoliko se proces car() definiše kao

@resumable function car(env::Environment)
    while true
        println("Start parking and charging at ", now(env))
        charge_duration = 5
        charge_process = @process charge(sim, charge_duration)
        try
            @yield charge_process
        catch
            println("Was interrupted. Hopefully, the battery is full enough ...")
        end
        println("Start driving at ", now(env))
        trip_duration = 2
        @yield timeout(sim, trip_duration)
      end
end;

i ako se ponovo pokrene simulacija dobija se:

sim = Simulation()
car_process = @process car(sim)
@process driver(sim, car_process)
run(sim, 15)

Start parking and charging at 0.0
Was interrupted. Hopefully, the battery is full enough ...
Start driving at 3.0
Start parking and charging at 5.0
Start driving at 10.0
Start parking and charging at 12.0

Može se zaključiti da je proces driver prekinuo aktivnost punjenja u procesu car nakon 3 v.j.

Deljeni resursi

Treba naglasiti da ConcurrentSim omogućuje tri tipa resursa za formiranje modela u okviru kojih više procesa mogu da dele korišćene resurse.

Osnovni tip resursa je opisan klasom Resource.

Neka u razmatranom primeru resurs predstavlja Stanica za punjanje baterija automobile i neka stanica ima dva mesta za punjenje. U tom slučaju se proces car() može opisati funkcijom:

@resumable function car(env::Environment, name::Int, bcs::Resource, driving_time::Number, charge_duration::Number)
    @yield timeout(sim, driving_time)
    println(name, " arriving at ", now(env))
    @yield request(bcs)
    println(name, " starting to charge at ", now(env))
    @yield timeout(sim, charge_duration)
    println(name, " leaving the bcs at ", now(env))
    @yield release(bcs)
end;

pri čemu je kao drugi argument definisanog procesa naveden deljeni resurs bcs. Upotreba resursa se vrši pozivanjem funkcija:

  • request() – za generisanje događaja za zauzimanje resursa, i

  • release() – za generisanje događaja za otpuštanje resursa.

Ukoliko se resurs zauzima, a on je već zauzet od strane drugog procesa, request će čekati da se resurs oslobodi, gde se redosled dobijanja resursa omogućava po FIFO principu. Kreiranje resursa se vrši sa:

sim = Simulation()
bcs = Resource(sim, 2);     # 2 mesta za punjenje, tj. 2 servisa

Nakon čega se mogu kreirati procesi sa različitim trajanjem vožnje (2,4,6 i 8) i trajanjem punjenja 5, pri čemu svi procesi dele dva resursa (bsc):

for i in 1:4
    @process car(sim, i, bcs, 2i, 5)
end

Događaji

ConcurrentSim omogućuje skup događaja različite namene koji su nasleđeni iz AbstractEvent klase. Najčešće se koriste:

  • Event

  • timeout

  • Operator

Događaji mogu biti u jednom od sledećih stanja:

  • idle - može se dogoditi,

  • scheduled – dogodiće se, ili

  • processed – dogodio se.

Inicijalno su događaji u stanju idle i funkcija state vraća ConcurrentSim.idle. Ako se događaj planira u određeno vreme on se postavlja u stanje ConcurrentSim.scheduled.

Sve dok se događaj ne obradi, njemu se mogu dodati povratni pozivi (callback funkcije). Povratna funkcija je funkcija koja ima kao prvi parametar AbstractEvent.

function my_callback(ev::AbstractEvent)
    println("Called back from ", ev)
end

sim = Simulation()
ev = Event(sim)
@callback my_callback(ev)
succeed(ev)
run(sim)

Called back from ConcurrentSim.Event 1

Primer - Pošta sa jednim redom čekanja

Ovaj primer simulira jedan red čekanja gde može biti više kanala opsluživanja (šaltera u pošti).

using ConcurrentSim, Random, Distributions, Printf

const RANDOM_SEED = 0
const UKUPNO_KLIJENATA = 10     # ukupan broj klijenata (stranki)
const INTERVAL_KLIJENTA = 5.0   # srednje vreme među dolazaka klijenta
const INTERVAL_SERVISA = 2.0    # srednje vreme obrade stranke


@resumable function dolasciKlijenata(env::Environment, broj::Int, interval::Float64, šalteri::Resource)
    vremenaMeđudolazaka = rand(Exponential(interval), broj)
    vremenaServisiranja = rand(Exponential(INTERVAL_SERVISA), broj)

    for i in 1:broj
        @yield timeout(env, vremenaMeđudolazaka[i])
        s = @sprintf "%2d" i        
        @process ponašanjeKlijenta(env, s * (" "^4i), šalteri, vremenaServisiranja[i])
    end
end

@resumable function ponašanjeKlijenta(env::Environment, naziv::String, šalteri::Resource, vremeServisiranja::Float64)
    t1 = now(env)
    @printf "%5.2f %s ušao\n" t1 naziv
    @yield request(šalteri)         # klijent čeka dok se ne oslobodi šalter
    dt = now(env) - t1
    @printf "%5.2f %s čeka %.2f na šalter %d\n" now(env) naziv dt šalteri.level

    @yield timeout(env, vremeServisiranja)
    @printf "%5.2f %s gotov!\n" now(env) naziv
    @yield release(šalteri)         # klijent "oslobađa" šalter
end

# inicijalizacija i pokretanje simulacije
Random.seed!(RANDOM_SEED);
env = Simulation()
brojŠaltera = 1
šalteri = Resource(env, brojŠaltera)
@process dolasciKlijenata(env, UKUPNO_KLIJENATA, INTERVAL_KLIJENTA, šalteri)
run(env)

θd = 5.0                        # sr. vreme izmedju dolazaka

for i = 2:n

Primer - Pošta sa dva... reda čekanja

Ovaj primer ilustruje upotrebu dva (ili više) reda čekanja, a može biti više kanala opsluživanja u svakom od njih. Konkretno, simulira se dva reda čekanja sa po dva šaltera.

using ConcurrentSim, Random, Distributions, Printf

const BROJ_REDOVA = 2
const RANDOM_SEED = 0
const UKUPNO_KLIJENATA = 20     # ukupan broj klijenata (stranki)
const INTERVAL_KLIJENTA = 5.0   # srednje vreme međudolazaka klijenta
const INTERVAL_SERVISA = 16.0   # srednje vreme obrade stranke

@resumable function dolasciKlijenata(env::Environment, broj::Int, interval::Float64, šalteri)
    vremenaMeđudolazaka = rand(Exponential(interval), broj)
    for i in 1:broj
        @yield timeout(env, vremenaMeđudolazaka[i])
        s = @sprintf "%2d" i 
        red = rem(i, 2) + 1     # izbor reda
        @process ponašanjeKlijenta(env, s * (" "^2i), šalteri[red], red)
    end
end

@resumable function ponašanjeKlijenta(env::Environment, naziv::String, šalteri::Resource, red::Int)
    t1 = now(env)
    @printf "%6.2f %s ušao u red %d\n" t1 naziv red
    @yield request(šalteri)
    dt = now(env) - t1
    @printf "%6.2f %s čeka %.2f na šalter %d:%d\n" now(env) naziv dt red šalteri.level
    @yield timeout(env, rand(Exponential(INTERVAL_SERVISA)))
    @printf "%6.2f %s gotov!\n" now(env) naziv
    @yield release(šalteri)
end

# inicijalizacija i pokretanje simulacije
Random.seed!(RANDOM_SEED);
env = Simulation()
brojŠaltera = 2
šalteri = [Resource(env, brojŠaltera) Resource(env, brojŠaltera)]
@process dolasciKlijenata(env, UKUPNO_KLIJENATA, INTERVAL_KLIJENTA, šalteri)
run(env)

Primer - Banka sa odustajanjem u redu čekanja

Ovaj primer proširuje prethodni tako što klijent staje u red (formiran zahteva za šalter rq = request(counter)), i njegovo čekanje nije samo da se šalter oslobodi (što bi bilo @yield rq, neko se kombinuje čekanja na dva događaja @yield rq | timeout(env, patience): 1) da se oslobodi šalter ili 2) da istekve vreme kada klijent gubi strpljenje (primetiti da je primenjena operacija "|" između događaja). Nakon dešavanja jednog od ova dva događaja proces klijenta (source) nastavlja sa radom i vrši se provera da li je state(rq) != ConcurrentSim.idle, što znači da je klijent dobio resurs, tj. došao je do šaltera pre nego je izgubio strpljenje.

I ovaj primer je preuzet kao originalan ConcurrentSim primer, tako da su nazivi promenljivih i ispisi na engleskom jeziku.

using ConcurrentSim, Random, Distributions

const RANDOM_SEED = 150
const NEW_CUSTOMERS = 5             # Total number of customers
const INTERVAL_CUSTOMERS = 10.0     # Generate new customers roughly every x seconds
const MIN_PATIENCE = 1.0            # Min. customer patience
const MAX_PATIENCE = 3.0            # Max. customer patience

@resumable function source(env::Environment, number::Int, interval::Float64, counter::Resource)
    d = Exponential(interval)
    for i in 1:number
        @process customer(env, "Customer$i", counter, 12.0)
        @yield timeout(env, rand(d))
    end
end

@resumable function customer(env::Environment, name::String, counter::Resource, time_in_bank::Float64)
    arrive = now(env)
    println("$arrive $name: Here I am")
    patience = rand(Uniform(MIN_PATIENCE, MAX_PATIENCE))
    
    rq = request(counter)
    @yield rq | timeout(env, patience)
    wait = now(env) - arrive
    if state(rq) != ConcurrentSim.idle 
        println("$(now(env)) $name: Waited $wait")
        @yield timeout(env, rand(Exponential(time_in_bank)))
        println("$(now(env)) $name: Finished")    
    else
        println("$(now(env)) $name: RENEGED after $wait")
    end
    @yield release(counter)
end

# Setup and start the simulation
Random.seed!(RANDOM_SEED);
env = Simulation()

# Start processes and run
counter = Resource(env, 1)
@process source(env, NEW_CUSTOMERS, INTERVAL_CUSTOMERS, counter)
run(env)

Primer - Mašine

U sistemu treba da radi n radnih mašina. Da bi se zaštitili od kvara mašine, dodatne mašine su na raspolaganju kao rezervni delovi. Kad god se neka mašina pokvari, odmah se zamenjuje rezervnom i šalje se na popravku jednom serviseru koji redom popravlja neispravne mašine. Nakon popravke mašine, ona postaje dostupna kao rezervna i može se ponovo koristiti kada se ukaže potreba. Sva vremena popravke su nezavisne slučajne promenljive koje imaju zajedničku funkciju distribucije G. Svaki put kada se mašina stavi u upotrebu, vreme za koje mašina funkcioniše, pre nego se pokvari, je slučajna promenljiva. Svi kvarovi su nezavisni od prošlosti, koja imaju funkciju distribucije F. Za sistem se kaže da će se "srušiti" kada mašina ne radi i ne postoje rezervne mašine. Pretpostavka je da u početku postoje n + s ispravne mašine od kojih se n stavlja u upotrebu, a s se čuvaju kao rezervne. Treba simulirati opisani sistem da bi se odredilo prosečno vreme do rušenja sistema E[T] (T je vreme kada se sistem ruši).

Prvo se opisuju procesi rada mašine i pokretanja simulacije, kao i funkcija koja simulira procese dok se ne desi "rušenje".

using Distributions, Random
using ResumableFunctions
using ConcurrentSim

const RUNS = 5
const N = 10
const S = 3
const SEED = 150
const LAMBDA = 100
const MU = 1

Random.seed!(SEED);
const F = Exponential(LAMBDA)
const G = Exponential(MU)

@resumable function machine(env::Environment, repair_facility::Resource, spares::Store{Process})
    while true
        try @yield timeout(env, Inf) catch end
        @yield timeout(env, rand(F))
        get_spare = get(spares)
        @yield get_spare | timeout(env)
        if state(get_spare) != ConcurrentSim.idle 
            @yield interrupt(value(get_spare))
        else
            throw(StopSimulation("No more spares!"))
        end
        @yield request(repair_facility)
        @yield timeout(env, rand(G))
        @yield release(repair_facility)
        @yield put(spares, active_process(env))
    end
end

@resumable function start_sim(env::Environment, repair_facility::Resource, spares::Store{Process})
    for i in 1:N
        proc = @process machine(env, repair_facility, spares)
        @yield interrupt(proc)
    end
    for i in 1:S
        proc = @process machine(env, repair_facility, spares)
        @yield put(spares, proc) 
    end
end

function sim_repair()
    sim = Simulation()                # postavljanje simulacionog okruženja
    repair_facility = Resource(sim)   # kreiranje resursa
    spares = Store{Process}(sim)      # kolekcija procesa
    @process start_sim(sim, repair_facility, spares)
    msg = run(sim)
    stop_time = now(sim)
    println("At time $stop_time: $msg")
    stop_time
end;
